翻译-压力下的个人任务管理（使用Org模式）

Personal task management under stress (with Org mode)

使用DeepSeek V4.1 Flash 翻译，以下为翻译全文：

[00:00:01.212] 开场介绍

大家好，我叫 Ihor Radchenko。今天我要讲的是用 Org Mode 进行个人任务管理。这个演讲的目的不是介绍任务管理的基础知识。相反，我要讲的是我在实践任务管理和 GTD(Getting Things Done)十年间遇到的一些问题，以及我是如何克服这些问题的。

[00:00:31.087] 我为什么做这个演讲

先讲一点背景。我个人在工作上以及业余时间里都要处理大量任务。比如，我在维护 Org Mode，这就需要盯邮件列表，基本上每周有一百多封邮件要处理。除此之外，我还要关注各种各样的社区软件包、论坛里的讨论，每周甚至每天都有大量任务。为了掌控这一切，我必须有一个非常好用的任务管理系统。

[00:01:13.784] 谁需要个人任务管理?

有这种需要的不止我一个。在座很多人看到这张截图应该会很眼熟:典型的就是浏览器里开着数不清的标签页-–—你当然打算以后有空时再看;或者收件箱里几千封未读邮件。

[00:01:34.777] 阶段一:临界点

当然，这个例子不只局限于浏览器。你还有工作任务、家庭事务，还要做一些线下的事情。当盘子里的事情太多时，一切就开始失控。而在事情开始失控的时候，很多人会倾向于拖延，这可不妙:如果你做得比平时还少，未完成的任务就会越积越多，形成向下的螺旋。

[00:02:21.460] 阶段二:圣杯

到了这一步，如果一个人真的被任务淹没，很多人就会开始研究各种任务管理系统，比如著名的 Getting Things Done、收件箱清零(Inbox Zero)，或者一些没那么知名的，比如看板(Kanban)、PARA 方法、艾森豪威尔矩阵。这有时候是有效的-–—至少当人们找到一套能坚持下来的方法时，最初的感觉非常好。

[00:02:51.430] 阶段三:熟练者

你开始把任务写下来。以我为例，我用的是 GTD，所以我会写任务，任何事都立刻写进所谓的“收件箱”，然后用待办列表去实际推进这些任务。有一段时间我甚至做了件很疯狂的事:把“吃早饭”也写成一个任务。最初几周感觉非常好，运气好的话，最初几个月都是如此。

[00:03:24.490] _{Emacs} GTD 破产(或:当 GTD 遇上现实生活)

但时间一长，这套东西就开始崩了，因为生活总会发生意外。你不可能总把事先计划的事都做完，任务不断累积，几十个、上百个。看这两张清单，问题跟收件箱一模一样:盘子里的东西太多，你甚至不知道该从哪儿开始。所有事情都在那儿，就是太多了。

[00:04:17.713] 阶段一:临界点(续)

于是我们又回到拖延的恶性循环。而这整套系统-–—其全部意义就在于掌控要做的事-–—也开始崩塌。这个过程往往呈周期循环:你走向破产，你更新系统，心想“这次肯定行”。但时间流逝，几个月、一年之后，又出了状况，系统又开始不灵，你又一次不知道该怎么办，于是再次调整。有些人干脆放弃，回到最原始的状态:不做任何任务管理，能做多少做多少，记得什么做什么。

[00:05:02.727] 走出恶性循环

我个人发现，其实可以总结出几条规则来应对任务管理中的这些长期问题。我能归纳出四条简单的规则:两条对初学者有用，另外两条对长期使用者很关键。

[00:05:21.115] 使用你的系统

第一条规则是:如果你把任务放在任务管理系统里-–—对我来说就是 Org Mode-–—那我就真的把所有任务都放在那里。我不会把一些待回复的邮件留在邮件收件箱里，另一些事记在脑子里，还有一些写在笔记本上，第四类又放进 Org Mode。这样做的结果并不好:这些散落的东西会让我绕开 Org Mode，因为我脑子里还挂着别的、我也需要追踪的事。这很常见，也是所有入门教程通常强调的重点:你确实需要使用这套系统，把一切都写下来。

[00:06:03.468] 养成习惯

第二点重要的是:如果你有一套系统，你就得用它。而且不是偶尔用用，而是每天用;每当你计划做点什么、思考要做什么的时候，你都要去找系统、找你的任务列表，并且真正去用它。这听起来也很显然，但确实非常重要。

[00:06:22.738] 排定优先级

第三条规则是随时间推移才显现出来的。一开始，写任务很容易，清单很短，也很好管理。但年复一年-–—对我来说大概十二年了-–—我手上有大约二十万个任务。我不可能全都做完，从物理上讲永远不可能。所以从长期看，给要做的事情排定优先级非常重要。有些事就是不会被完成，永远都不会。这就是生活。

[00:06:53.992] 为意外做计划-–—事情出错时，规划好恢复方案

第四条重要的规则是:生活总会有意外，你有时就是无法按计划行事，有时不得不立刻去做某件事，不管你原来的计划是什么。如果这种事发生得足够多，系统就会崩溃。无论这套系统多么复杂、多么聪明，它都会崩溃。所以必须有一个“坏事情发生之后”的方案:怎么恢复、怎么回到使用系统的状态。这个方案才是能让你在多年里一直用下去的关键。让我举一些更具体的例子。就我而言，重点会放在 GTD 和 Org Mode 上。

[00:07:42.958] 使用你的系统:从电脑上 org-capture

所以第一条规则就是把事情写下来，对我来说就是写进 Org Mode。我所有的任务都在 Org Mode 里。比如我想到任何要做的 事，我就在电脑上按一个键，用 org-capture，然后把任务记下来。如果我正忙着别的事，突然冒出一个想法，我不会把它记在脑子里。我按一个键，org-capture，任务就存好了。我很确信它会在那里，我之后再去看它，而在此期间我可以继续做手上的事。

[00:08:18.234] 使用你的系统:从邮件中 org-capture

对别的东西也一样，比如邮件。如果我来了一封邮件，我就用 org-capture，它就会进到我的待办列表里-–—和记录我其他想法的同一个待办列表。

[00:08:31.265] 使用你的系统:从浏览器中 org-capture

网站、社交媒体、博客等等也是一样。在浏览器里我按一个键，用 org-capture，配合 org-protocol，它就存进我的待办列表，和其他所有东西进的是同一个待办列表。

[00:08:47.256] 使用你的系统:从 RSS 源(elfeed)中 org-capture

同样，其他事情也是如此。比如我实际的工作是做研究，所以我需要跟踪新的出版物，于是我用 RSS 源、用 elfeed，在那里我按一个键，用 org-capture，它就和所有其他东西一样进到同一个待办列表。

[00:09:07.693] 使用你的系统:从手机上 org-capture(在外出途中)

即使我不在电脑旁，我也可以直接用手机，在手机上把任务写下来，它就会进入与我电脑同步的 Org 文件里。

[00:09:18.236] 一致地使用你的系统

所以最终，所有东西都会汇入同一个我可以推进的待办列表。我不会把它拆散成“噢，这个我得记住”“我得查邮件，也许在邮件里”“我不记得放哪儿了，也许写在某张纸上了”-–—那样我根本追踪不了。所有东西集中到 Org Mode，所以当我需要决定做什么时，我直接切到 Org Mode，一切总是在那儿。当然，这是我个人的做法。我知道对有些人来说稍微不同的方式也管用，因为有些人更喜欢只用任务管理来处理工作或生活中某个非常专门的领域，比如只把与工作相关的条目交给待办系统管理，家庭的事就照常顺手处理。这样也行，但它必须是一致的:如果所有与工作相关的条目都由任务管理来管，那它就应该全部进入任务管理，没有例外。你需要划出清晰的边界。所以在理想情况下，对于某个领域里的所有事情，每当你需要思考“我要做什么”时，你都会去找你的任务管理系统并直接在其中工作。

[00:10:40.992] 习惯:每天检查任务(通过 org-agenda 或其他方式)

这个过程需要习惯。这是我待办列表的一个例子。我个人使用 org-agenda，不过并不一定要用 org-agenda。在 Org 里管理任务还有别的方式，比如每天直接手写任务清单。但在我的做法里，我用的是重复任务:第一，所有已安排的任务会自动出现在议程里;第二，我有每天回顾它们的任务，用来决定今天实际要做什么。我每天早上做这件事-–—每当我坐到工作或家里的电脑前、需要决定做什么时，我都会做。我把它做成一个按键绑定，每次我坐下来打开 Emacs 时就会触发。

[00:11:41.646] 一旦一个习惯建立起来，它可以挂接更多习惯

一旦我建立了这个习惯，我就能在上面叠加很多东西。仅仅是每天早晨打开议程这个练习，就让我能做更多事。我有一个重复任务，是去邮件收件箱，把所有东西都捕获到待办列表里，这样我就不必一整天操心写任务;我每天做一次，但每天都做。社交媒体也是一样。IRC、WhatsApp 之类的消息也是一样。我甚至有用于记账、甚至用于在网站上发帖的每日任务。所以一旦有了这个核心的使用议程做待办列表的习惯，我就能在此基础上一点点搭建-–—这花了我很多很多年-–—我不断加入我认为需要做的事。这样我就能建立起相当复杂的结构，它真的帮我把各种事情以同样的方式管理起来。

[00:12:55.043] 用习惯控制你的注意力(续)

当然，做起来并不总是容易。即使我有习惯，社交媒体这类东西本来就是专门设计来分散你注意力的。有各种各样的手机通知、应用通知，关于各种各样的事。比如我很讨厌 LinkedIn，它不停地推送我根本不关心的通知，而且除了彻底关闭之外我甚至无法禁用。所以我的做法是每天或每周划出特定时间。社交媒体是按周。对社交媒体，我有不同的处理方式:我给它固定的时间，比如二十分钟、半小时，但每天只做一次，或者每周一次，甚至每几周一次。这样我仍然会看，但不必被源源不断的通知打扰。这种时间分块的做法，多次把我从社交媒体的干扰中救了出来。

[00:14:13.156] 优先级:三层议程

好，第三条规则是排定优先级。当你有一个非常非常长的任务列表时，这就变得很重要。比如我要处理几百封邮件，无论我怎么组织，我还是得处理几百封邮件，再加上我的实际工作和其他事情。我的体会是:状态好的日子我能做很多事，状态差的日子我能做的少得多。所以我在规划任务时设了三个层级。第一层基本就是今天的议程，也就是我必须做的事。这清单在一天开始时通常更长，但到了早上、我实际知道当天会发生什么之后，我会把它缩短。这些任务是我重点关注的对象。我尽量把它们安排成能做完的量，并试着在当天全部完成。这是我所说的“专注议程”。然后是普通议程:重要的任务，再加上一些我想做但并非必须做的额外任务。如果这天状态好、有空闲时间，那好，我可以把它们也完成。还有第三层:当我这天状态真的很好，把当天计划的事全做完了，我还有一些原本打算在这一周里做的额外任务，那就在时间充裕或提前完成时去看这个列表。

有了这三个层级，我的目标始终是让必须做的那份清单保持非常短，其他东西都放在视线之外，这样我就不会被待办事项的数量压垮-–—至少对我而言，那会相当令人泄气。

[00:16:21.473] 优先级:学会说“这个我不做!”

这些列表，尤其是那些更长的、为一周准备的列表，我也得让它们保持在合理范围。因为如果我几周没空看邮件列表，那很快就会变成三四周百封邮件，对我来说就是三四周百个任务，看着有点吓人。所以我必须排优先级-–—不只是针对某一天，而是基本上按周甚至按年排序。我的做法是:遇到新任务时，我首先判断，如果这个任务我根本不打算做，我就把它标成 someday(某天)，它就会落到我很少去看的地方。但也有一些事我真的很想做，而现实是我无法把想做的事全做完。所以我尽量做每周回顾，看看前一周计划的任务列表，如果它变得太长就处理一下。这意味着有些任务就是做不成，我要么把它们标成 someday，要么，如果我觉得“我真的很想做但做不了”，我就把它标成所谓的“on hold”(挂起)，这样任务会从议程中消失，但也许下周我还会看到它。用这个办法，我提前一周做计划，估计那一周我能完成什么，尽量让任务列表保持合理，好让我真的能做完。这有效，但从长期看仍然不够好。

[00:18:27.101] 优先级:按项目/主题批量管理任务

因为当你面对成千上万的任务时，你不可能全都看一遍，甚至每周看一遍都做不到，更不用说每天了。我的解决办法是层级结构:基本上按主题或项目把任务分组。当我规划一周、看到事情实在太多时，我不会逐个任务去决定“这个做还是那个做”，而是先决定:我要不要做整个这个项目?或者要不要做某个领域?例如，下周我要不要看 YouTube?有时候我说，不行，我真没时间，就整个关掉、挂起，下周再重新考虑。或者我有五个项目在进行，我不可能在同一周都做，那就把其中一些挂起。有时有件我真的很想做的事，但看起来没时间，我就把它放到 someday。这样我就能按任务组来管理，不必每次都在成百上千个任务里翻。这些是每周做的。

[00:19:48.361] 年度回顾

在更粗的尺度上，我还有年度回顾。我有一个装着我很感兴趣的一些非常笼统的主题或领域的桶。对某一年，我会想:好，也许接下来这一年我想去学点生物学，因为我对某些书签一直很好奇，却总没时间。我会周期性地更换这些主题，与往年相比有所变化，这样我能持续学新东西。思路同样是:我持续从同一处学习，以免让自己过载。

[00:20:38.608] 即使最好的系统也会出错

这一切都很好，但无论如何-–—我可以做每天的议程、做好优先级、做每周回顾、年度回顾等等-–—生活还是会发生意外。可能停电，笔记本电脑坏了，或者突然来了个[辨听不清]截止期限，或者我住院了，任何事都可能发生。我可能无法使用我刚才描述的这一切。所以无论计划是什么、系统多复杂，事情都可能出错，我必须应对。我的解决办法是:我必须有一个“在我无法跟进事情之后如何恢复”的方案。

[00:21:26.257] 恢复示例:为 Org 邮件列表做时间分块

这是一个例子。有一段时间，我在实际工作上事务繁重，实在没多少时间，所以我无法跟进 Reddit、Emacs Life、Emacs Planet 以及我通常关注的这些社区帖子和内容，结果积攒了好几千条未读书签，我一直没时间看。这种情况下，我就用时间分块的办法:我不去看那几千个标题、纠结拿它们怎么办，而是规定自己每天花十五分钟，能看多少看多少，就这样，一天结束。我每天坚持这么做，于是经过[辨听不清]几周，我就能真正追上进度。

[00:22:28.097] 恢复示例:项目过载

我常做的另一种办法是:当我确实有太多事时，就把某些项目或某些主题挂起，让工作量保持在合理范围。即使我必须做点什么，我也得现实一点，按我实际拥有的时间来分配。比如，当我很久没能跟进待办列表、积压了很多事时，我就很激进地把事情挂起，甚至标成 someday。这样我仍然能把任务量控制在合理范围，让系统不至于把我压垮，并在我能重新使用系统的时候照常运转。

[00:23:16.622] 恢复的关键在于优先级

所以关键规则-–—我认为这也是最重要的一条-–—是:当事情出错时，我做的第一件事是回到我惯常的习惯，真正去使用、回顾我的待办列表。但我会非常激进地排优先级，看看哪些是最不重要的，把它们标成 someday;把事情挂起，因为我一天只有二十四小时。如果我确实要处理大量任务，我就用时间分块。然后快速地重复这个过程，这样我就能尽可能慢慢地追上进度。这样一来，我描述的所有这些组件就能让整套系统持续运转，即使中途有中断、无法使用我的任务管理系统。

[00:24:16.974] 长期管理任务:四条规则

总结一下，回到我开头介绍的四条规则。第一条，也是最关键的规则，对初学者和长期使用任务管理的人都重要:如果你有这套系统，你就真的要把任务存在系统里。你划定使用它的范围，而在那个范围之内，你确实要对一切事情都用它。不要把自己分散到多种不同的做法上。第二条规则是:使用系统应当成为习惯。比如你有待办列表，那就每天去回顾它，不要跳过，不要 basically 忽略它，因为一旦被忽略，它就是被忽略了，根本没有被用起来，也就变得毫无用处。第三条规则在你长期使用任务管理之后才变得重要，那就是排定优先级。因为随着时间推移，总会有大量任务。不可能把所有东西都写下来、同时又全都做完，因为人脑子里的想法太多了，其中大多数永远不会被完成。所以你必须排优先级，必须决定哪些该做、哪些干脆不做，或者至少决定接下来一周、一个月或一年该聚焦什么。你不可能什么都做。第四条，也是最重要的规则:你应当有一个方案，用来应对生活中发生紧急状况之后如何恢复，因为这类事确实会发生，尤其是在很长一段时间里。比如你活上十年，那当然会有事发生。生活并不总是平顺的。我的演讲就到这里，非常感谢大家的关注。欢迎提问，如果你们感兴趣，我也可以展示更多细节。
